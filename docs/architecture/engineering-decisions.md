# Architectural Decision Records (ADRs)

본 문서는 `krx-alpha` 시스템의 핵심 기술적 결정사항(Architecture Decision Records)을 기록합니다. 단순 기능 목록을 넘어, 프로덕션 환경의 제약, 대안 평가, 채택 이유 및 트레이드오프를 엔지니어링 관점에서 엄밀히 다룹니다.

## 2. Detailed Technical Decisions

### ADR-01: 2단계 유니버스 수집 정책 (일봉 배치 필터 + 장중 WS 스트리밍)
* **Decision**: 국내 주식 전종목(2,500+)을 실시간 스트리밍하지 않고, 장전(08:20) 공식 일봉 데이터를 바탕으로 단타 유니버스(최대 90종목)를 선별하여 웹소켓으로 수집한다.
* **Context**: 전종목 동시 수집은 리테일 증권사 웹소켓 커넥션당 한도(LS 200쌍, KIS 41쌍)를 초과하며, 저사양 클라우드 VPS(RAM 500MB, 3GB 워터마크)의 디스크를 수일 내 고갈시킴.
* **Selected Approach**: 최근 60영업일 일봉 기준 상한가(`limit_up`), 10% 급등(`surge10`), 거래대금 급증(`volsurge`), 60일 신고가(`newhigh60`) 조건과 50억 유동성 필터를 적용하여 최대 90종목으로 압축.
* **Rationale**: LS증권 단일 커넥션 기술용량(200쌍) 내에 100% 수용하여 다중화 연결 관리 복잡도 제거. $T-1$ 거래일 종가만 참조하는 Look-Ahead 방어벽 내장.
* **Trade-off**: 장 시작 후 장중에 갑작스럽게 호재가 발생한 신규 급등주는 당일 수집 대상에서 제외됨.

### ADR-02: 3계층 스토리지 & Offload-before-Delete 원칙
* **Decision**: 실시간 틱은 원문 그대로 L0 저널(JSONL.zst)에 append-only로 적재하고, 장마감 후 배치 단계에서 검증 후 L1 Parquet로 변환하며, Google Drive 업로드 크기가 바이트 단위로 일치 확인된 파티션만 로컬 삭제한다.
* **Context**: 수집 루프에서 고부하 파싱과 Parquet 압축을 동시 수행하면 이벤트 루프가 블로킹되어 웹소켓 버퍼 오버플로우가 발생함. 반대로 단순 기간 경과 삭제를 적용하면 업로드 실패 시 원본이 영구 유실됨.
* **Selected Approach**:
  1. `L0 저널`: 무파싱 raw 문자열 + 나노초 시각(`recv_mono_ns`, `recv_wall_ns`) + 연결 시퀀스를 zstd 압축 저널에 append.
  2. `EOD DQ 배리어`: Polars 벡터 연산으로 누적체결량 보존법칙, 가격제한폭($\pm 30\%$), 호가 사다리 단조성 검증. 실패 파티션은 `quarantine/` 비파괴 격리.
  3. `원격 대사`: `rclone lsjson` 접두사 단건 조회로 원격 바이트가 일치함을 확인한 경우에만 로컬 L0/L1을 순환 삭제.
* **Trade-off**: EOD 시점에 L0 역압축, DQ 검증, Parquet 변환을 일괄 수행하기 위한 일시적 연산 부하가 요구됨.

### ADR-03: NTP 실측 기반 Fail-Closed 클럭 게이트
* **Decision**: 세션 부트스트랩 시 외부 타임서버(`kr.pool.ntp.org`)와의 클럭 오프셋을 실측하여 2.0초 초과 또는 통신 불가 시 프로세스 시작을 즉시 거부(`ClockUnsyncedError`)한다.
* **Context**: 클라우드 가상머신 및 WSL2 환경은 호스트 슬립/웨이크업으로 인해 시스템 시계가 +1000ms 이상 왜곡되는 현상이 빈번함. 시간이 왜곡된 틱은 이벤트 발생 순서가 역전되어 백테스트 신뢰성을 훼손함.
* **Selected Approach**: 5개 샘플의 중간값(median) 오프셋을 측정하여 2.0초 이내인 경우에만 수집 세션을 허용. 모든 틱 레코드에 단조 시계와 벽시계를 병기.
* **Trade-off**: 세션 기동 시 외부 UDP 123 포트 통신이 필수적이며, 네트워크 단절 시 세션 진입 불가.

### ADR-04: 단일 OMS 기반 Dual Gateway 분기 (Paper 섀도 vs Live 무장)
* **Decision**: 주문 관리 시스템(OMS)과 사전 리스크 게이트는 단일 인터페이스를 유지하고, 하위 전송 계층만 `PaperGateway`와 `LiveGateway`로 분기하며, Live 모드는 `KRX_ALPHA_EXEC_LIVE_ARMED=true` 환경변수가 없으면 인스턴스화를 원천 차단한다.
* **Context**: 모의 로직과 실전 로직이 분리되어 있으면 프로덕션 전환 시 구현 불일치로 금융 사고가 발생할 위험이 높음.
* **Selected Approach**:
  - `PaperGateway`: KIS 실계좌 잔고를 조회하되 실제 거래소 소켓은 연결하지 않고, 실시간 10단계 호가 잔량을 소진하는 모의체결(`paper_l10_sweep_v1`) 및 전송 직전 바디 저널링(`paper_would_send`) 수행.
  - `LiveGateway`: KIS REST 실주문 전송.
* **Trade-off**: 호가 대기열 우선순위(Queue Priority) 및 시장 충격(Market Impact)은 완벽히 모사하지 못함.

### ADR-05: AST 정적 분석 기반 아키텍처 불변식 테스트
* **Decision**: 모든 모듈 간 의존성 계층 랭크(Layer 0~7), 파일시스템 경로 리터럴 사용, 환경변수 접근을 `tests/architecture/` 내부의 pytest 단위 테스트에서 Python `ast` 모듈을 사용해 정적으로 파싱하여 강제한다.
* **Context**: 지속적 리팩토링 과정에서 모듈 간 상위 레이어 역참조, 순환 의존, 하드코딩된 경로 생성으로 인한 아키텍처 침식을 방지하기 위함.
* **Selected Approach**:
  - 하위 $\to$ 상위 레이어 임포트 0건 강제.
  - `src/core/config.py`의 `DataPaths` 외 임의 `Path("...")` 리터럴 생성 0건 강제.
  - `os.environ` / `os.getenv`의 단일 소스 격리.
* **Trade-off**: 새 모듈 추가 시 `tests/architecture/layers.py` 계약 테이블을 갱신해야 함.

### ADR-06: 다중 벤더(토스·KRX·KIS) 결합 탄력적 오케스트레이션 및 휴장일 게이트
* **Decision**: 영업일 판정은 토스증권 메타데이터 API를 게이트로 활용하고, 일봉 수집은 KRX 공식 API를 1차로 하되 장애 시 KIS REST 일봉 조회로 1회 폴백한다.
* **Context**: 단일 벤더 장애(점검, 네트워크 절단) 시 전체 무인 수집이 중단되는 SPOF를 제거하고, 주말/공휴일 오기동을 방지하기 위함.
* **Selected Approach**: `TradingDayGate`를 통해 날짜당 1회 영업일을 확정하고, KRX 일봉이 직전일 대비 90% 미만으로 절단되거나 실패 시 KIS `FHKST03010100`으로 자동 폴백.
* **Trade-off**: 복수 브로커의 자격증명 관리가 필요함.

### ADR-07: 거래소 개편 반영 세션 분리(`market_phase`) 및 멀티 벤더 DQ 배리어
* **Decision**: 2026-09-14 거래소 제도 개편(애프터마켓 16:00~20:00 신설)에 따라 파티션명이 아닌 거래소 시각 기반 `market_phase`를 L1에 부여하고, LS JSON과 KIS 캐럿(`^`) 틱 포맷을 개별 디코더로 분리 검증한다.
* **Context**: 16~20시 체결 틱이 정규장 파티션에 혼입되어 백테스트 세션 필터링이 오염되었으며, KIS 캐럿 틱을 LS JSON 디코더로 파싱 시 100% 디코딩 실패로 오판되는 결함이 존재했음.
* **Selected Approach**:
  - `market_phase` 컬럼으로 정규장/애프터마켓/동시호가 구분을 확정.
  - `quality_ls.py`와 `quality_kis.py`를 독립 구현하여 벤더별 틱 보존법칙과 호가 사다리를 검증하고 비율 기반 PASS/WARN/FAIL을 L1 메타데이터에 기록.
* **Trade-off**: KIS 호가 디코딩 연산(EOD 1회성, 약 2.9초)이 추가됨.

### ADR-08: 장중 무중단 배포(Deploy Continuity), PID 1 시그널 전파 & 토큰 자가복구
* **Decision**: 평일 장중(08:10~22:00) CI 배포는 컨테이너 재생성을 유예하고 22:00 야간 타이머로 이관하며, 데몬 프로세스에 SIGTERM 전파기 및 KIS 토큰 자가복구 로직을 적용한다.
* **Context**: 도커 PID 1 프로세스가 SIGTERM을 처리하지 못해 30초 후 SIGKILL로 강제 종료되었고, 장중 배포 푸시 시 컨테이너 재생성으로 인한 실시간 틱 수집 공백이 발생했음. 또한 사전 토큰 발급 실패 시 하루 종일 REST가 중단되는 취약점이 있었음.
* **Selected Approach**:
  - `deploy_gate.py`: 장중 배포 유예로 틱 수집 공백 0건 보장.
  - SIGTERM/SIGINT 전파 핸들러와 20초 데드라인으로 자식 수집기 정상 종료 및 버퍼 플러시.
  - 캐시 토큰 부재 시에만 공유 락과 65초 백오프로 장전(08:20) 자동 갱신.
* **Trade-off**: 장중 릴리즈된 최신 코드는 22:00 이전까지 즉시 적용되지 않고 야간에 반영됨.
